# تقرير العمل — DroidShield AI

**المشروع:** نظام لكشف البرمجيات الخبيثة في تطبيقات أندرويد بالتحليل الساكن والتعلّم الآلي والذكاء الاصطناعي القابل للتفسير (SHAP)
**المستودع:** https://github.com/Mohammaddkdjd/droidshield-ai
**تاريخ التقرير:** 26 نوفمبر 2026

---

## 1. ملخص

DroidShield AI يستقبل ملف APK، ويحلّله تحليلاً ساكناً دون تشغيله، ثم يستخرج منه متجه ميزات من 110 إذناً، ويصنّفه نموذج SVM إلى «سليم» أو «خبيث»، ويشرح سبب القرار بقيم SHAP. يعمل النظام كاملاً في Docker: خادم FastAPI وواجهة React عربية.

| البند | القيمة |
|---|---|
| وحدات التحليل الساكن | 12 وحدة |
| عدد الميزات | 110 إذن Android |
| النموذج | SVM (نواة RBF) معايَر احتمالياً |
| الدقة على بيانات الاختبار | 91.5% |
| ROC-AUC | 0.961 |
| الاختبارات الآلية | 198 اختباراً |

---

## 2. البيانات

- **المصدر:** `Final_Balanced_Three_Datasets.csv` (دمج ثلاث مجموعات بيانات)، فيه 110 عموداً لأذونات Android وعمود التصنيف.
- **التنظيف:**

| المرحلة | عدد الصفوف |
|---|---|
| الصفوف الأصلية | 18,412 (12,888 خبيث · 5,524 سليم) |
| بعد حذف التكرار | 3,580 |
| حذف صفوف متعارضة (نفس الميزات بتصنيفين مختلفين) | −166 |
| **البيانات النظيفة** | **3,414** (2,290 سليم · 1,124 خبيث) |

- **التقسيم:** 2,731 للتدريب و683 للاختبار، تقسيماً طبقياً.
- **ملاحظة مهمة:** معظم الصفوف الأصلية كانت مكرّرة. حذف التكرار يمنع تسرّب البيانات بين التدريب والاختبار، ويجعل الأرقام المعلنة واقعية.
- **قفل المخطط:** يُقرأ ترتيب الميزات من رأس ملف البيانات، ويُثبَّت ببصمة SHA-256. الخادم يرفض التشغيل إذا لم تطابق بصمة النموذج بصمة المحرك، وبهذا لا يمكن أن يختلف ترتيب الميزات بين التدريب والتشغيل.

## 3. محرك التحليل الساكن (`backend/droidshield_engine`)

بُني المحرك على عشر مراحل، وكل مرحلة لها اختباراتها.

**النواة:**
- **`apk_loader` و`zip_inspector`:** فتح ملف APK بأمان. القراءة محدودة الحجم للحماية من قنابل الضغط (zip bomb)، ويُكشف التلاعب في بنية ملف ZIP.
- **`dex_loader` و`string_pool`:** قراءة ملفات DEX ومجمّع النصوص.
- **`budget`:** حدود للوقت والذاكرة لكل تحليل.

**وحدات التحليل (12 وحدة):**

| الوحدة | ما تستخرجه |
|---|---|
| Manifest | الحزمة، الإصدار، SDK، الأذونات، ومنها `uses-permission-sdk-23` |
| Permissions | تصنيف الأذونات، وما يقع منها خارج النموذج |
| Components | الأنشطة والخدمات والمستقبِلات المكشوفة لتطبيقات أخرى |
| DEX | الأصناف والدوال |
| API | استدعاءات API الحساسة مصنّفة في 18 فئة (SMS، تحميل كود ديناميكي، Reflection…) |
| Strings | عناوين IP والمنافذ المكتوبة في الكود، وأوامر shell |
| Network | سياسة HTTP غير المشفّر (Manifest وNetwork Security Config) |
| Certificate | التوقيع (v1/v2/v3)، وشهادات Debug |
| Native | المكتبات الأصلية (.so) |
| Resources | الموارد |
| Hardware | الميزات العتادية المطلوبة |
| Metadata | الحجم والبصمات |

**تحويل النتائج إلى ميزات (`feature_extraction`):**
- القاعدة: الميزة F = 1 إذا طلب التطبيق `android.permission.F`.

**التصدير:** JSON وNumPy وتقرير نصي، مع وضع دفعي (batch) لتحليل مجلد كامل.

**مشاكل اكتُشفت في Androguard 4.1.4 وعولجت:**
1. الدالة `get_permissions()` تتجاهل `uses-permission-sdk-23`. **الحل:** المحرك يقرأ XML الـ Manifest بنفسه.
2. محلّل ZIP في Androguard يفكّ الضغط دون حدّ. **الحل:** دالة قراءة محدودة خاصة بالمحرك.
3. أُصلحت إنذارات كاذبة في كشف عناوين IP، كانت تلتقط معرّفات OID مثل `0.0.9.00`.

## 4. النموذج (`backend/ml/train_droidshield.py`)

- **الخوارزمية:** `CalibratedClassifierCV(SVC-RBF)`. أفضل المعاملات من البحث الشبكي: `C=10` و`gamma=scale`.
- **النتائج على بيانات الاختبار (683 تطبيقاً):**

| المقياس | SVM (النموذج) | Logistic Regression | الفئة الأغلب |
|---|---|---|---|
| Accuracy | **91.5%** | 87.3% | 67.1% |
| Balanced Accuracy | **90.7%** | 88.1% | 50.0% |
| F1 (خبيث) | **0.873** | 0.824 | 0.000 |
| ROC-AUC | **0.961** | 0.941 | 0.500 |
| إنذار كاذب (FPR) | **7.0%** | 14.4% | — |
| خبيث فائت (FNR) | 11.6% | 9.3% | 100% |

- **مصفوفة الالتباس:** 426 سليماً صحيحاً · 32 إنذاراً كاذباً · 26 خبيثاً فائتاً · 199 خبيثاً مكتشفاً.
- **التفسير:** SHAP مع عيّنة خلفية محفوظة، ويُظهر لكل تطبيق الأذونات التي دفعت القرار نحو «خبيث» أو «سليم».
- **ملفات النموذج:** `backend/models/droidshield/`:
  - `svm_rbf.joblib`
  - `model_card.json` (يحمل البصمة)
  - `metrics.json`
  - `feature_names.json`
  - `shap_background.npy`

## 5. الخادم (`backend/app`)

نقاط FastAPI:

| النقطة | الوظيفة |
|---|---|
| `GET /health` | حالة الخادم |
| `GET /model/info` | معلومات النموذج ومقاييسه |
| `POST /predict` | رفع APK، ثم تحليل وتنبؤ وتفسير |
| `POST /predict/features` | تنبؤ من متجه ميزات مباشرة |

**الأمان:**
- كل ملف يُحلَّل في **عملية معزولة** مهلتها 300 ثانية، فلا يستطيع ملف خبيث أو تالف إيقاف الخادم.
- الحد الأقصى لحجم الملف 100 MB.
- التحقق من قيم الميزات: يُقبل 0 أو 1 فقط.
- ذاكرة مؤقتة: الملف الذي فُحص سابقاً تُعاد نتيجته فوراً.
- الملف `engine_bridge.py` يحوّل مخرجات المحرك إلى صيغة الواجهة، ويضيف حقل `analysis` بمعلومات المحرك الوصفية.

## 6. الواجهة (`frontend`)

React 18 وVite، بالعربية وباتجاه RTL، مع وضعين فاتح وداكن.

**الصفحة الرئيسية:**
- منطقة رفع بالسحب والإفلات، تعرض مراحل التحليل أثناء الانتظار.
- شريط بأرقام النموذج الحقيقية، تُقرأ من الخادم.
- قسم «كيف يعمل» من أربع خطوات.

**صفحة النتيجة:**
- **بطاقة الحكم:** ملوّنة حسب النتيجة (آمن، مشبوه، خبيث)، مع بيانات التطبيق وتنزيل التقرير بصيغة JSON.
- **بطاقات مؤشرات:** احتمال الخبث، الثقة، عدد الأذونات، زمن الفحص.
- **رسم SHAP:** يفسّر القرار.
- **«ماذا وجد المحرك داخل التطبيق؟»:**
  - فئات API الحساسة، المكوّنات المكشوفة، سياسة HTTP، التوقيع، الخوادم، أوامر shell.
  - يوضّح القسم أن هذه المعلومات لا تدخل في قرار النموذج.
- **شريط تنقّل بين الأقسام:** يبقى ظاهراً عند التمرير.

**تفاصيل أخرى:**
- تذييل يعرض مقاييس النموذج، وتنبيه بأن النتيجة تقدير إحصائي، ورابط المستودع.
- **التحقق:** صور شاشة في الوضعين الفاتح والداكن، وعلى عرض هاتف 390px.
- **تصحيح نصوص قديمة:** حُذف ادعاء «7,000 تطبيق»، والرقم 215 من نموذج Drebin القديم.

## 9. سجل الإصلاحات

| المشكلة | الحل |

## 10. القيود والتطوير المستقبلي

**القيود:**
- النموذج يعتمد على **الأذونات فقط**. الأذونات الحديثة غير الموجودة في بيانات التدريب لا تدخل في القرار.
- التحليل ساكن، فلا يكشف السلوك الذي يظهر وقت التشغيل فقط أو الكود المشفّر.
- النتيجة تقدير إحصائي، وليست حكماً قاطعاً.

**التطوير المستقبلي:**
- إدخال ميزات المحرك الأخرى (API والمكوّنات والشبكة) في النموذج.
- التدريب على بيانات أحدث وأكبر.
- إضافة تحليل ديناميكي.
